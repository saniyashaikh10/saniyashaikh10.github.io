Case Study 02

SQL Data Exploration

The KPIs everyone quotes in meetings, calculated properly — joins, CTEs, and window functions doing the work spreadsheets can't.

SQL SQLite KPIs
01

Business Problem

Most "SQL practice" is isolated exercises against a single table. Real business databases are relational — customer, product, and order data live in separate tables that have to be joined correctly to answer even simple questions. I built a proper relational database from the same retail dataset used in Project 01, and queried it the way an analyst actually would.

02

Approach

  • Normalized a flat 10,000-row CSV into four relational tables — customers, products, orders, order_items — connected by ID keys, mirroring a real business schema
  • Loaded into SQLite and queried directly with SQL via Python
  • Progressed from multi-table joins → CTEs → window functions, each answering a genuine business question
03

Multi-Table Join: Top Customers by Profit

Customer names live in one table, profit figures in another. A three-table join (order_items → orders → customers) connects them.

SELECT c."Customer Name", c.Segment,
       ROUND(SUM(oi.Profit), 2) AS total_profit,
       COUNT(DISTINCT oi."Order ID") AS num_orders
FROM order_items oi
JOIN orders o ON oi."Order ID" = o."Order ID"
JOIN customers c ON o."Customer ID" = c."Customer ID"
GROUP BY c."Customer ID"
ORDER BY total_profit DESC
LIMIT 5

04

CTE + CASE: Customer Value Tiers

A CTE isolates the join/aggregation logic, so the outer query can cleanly apply business rules — here, bucketing customers into value tiers.

WITH customer_totals AS (
    SELECT c."Customer ID", c."Customer Name", c.Segment,
           SUM(oi.Profit) AS total_profit
    FROM order_items oi
    JOIN orders o ON oi."Order ID" = o."Order ID"
    JOIN customers c ON o."Customer ID" = c."Customer ID"
    GROUP BY c."Customer ID"
)
SELECT "Customer Name", Segment, ROUND(total_profit, 2) AS total_profit,
    CASE
        WHEN total_profit > 5000 THEN 'High Value'
        WHEN total_profit > 1000 THEN 'Medium Value'
        ELSE 'Low Value'
    END AS customer_tier
FROM customer_totals
ORDER BY total_profit DESC

This pattern — CTE to calculate, outer query to classify — is one of the most common real-world SQL structures, and directly answers a typical stakeholder ask: "who are our high-value customers?"

05

Window Function: Top 3 Products per Category

RANK() OVER (PARTITION BY ...) ranks rows within groups without collapsing them — impossible to do cleanly with GROUP BY alone.

WITH product_profit AS (
    SELECT p.Category, p."Product Name", SUM(oi.Profit) AS total_profit
    FROM order_items oi
    JOIN products p ON oi."Product ID" = p."Product ID"
    GROUP BY p."Product ID"
),
ranked AS (
    SELECT Category, "Product Name", ROUND(total_profit, 2) AS total_profit,
           RANK() OVER (PARTITION BY Category ORDER BY total_profit DESC) AS rank_in_category
    FROM product_profit
)
SELECT * FROM ranked WHERE rank_in_category <= 3
ORDER BY Category, rank_in_category

Window Function: Running Total

A running total — one of the most common real interview and take-home SQL tasks — using a window function with no PARTITION BY, so it accumulates across every row in date order.

Sales grew consistently year over year, reaching £2.3M cumulative by the end of 2017 — Q4 (Oct–Dec) is consistently the strongest period each year, a useful seasonal signal for planning.
